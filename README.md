# Вагонотека

*Всё о вагоне — в одном месте.*

Справочник по грузовым вагонам: характеристики, тележки и запчасти, сроки
ремонта, сертификаты, допустимые грузы (поиск по 1 870 видам груза),
вагоностроительные заводы и ремонтные депо. Собран из внутренней
Excel-выгрузки, чтобы сотрудникам не приходилось искать всё это вручную по
справочникам.

Сайт статический — весь код в [`docs/`](docs/), данные читаются из
[`docs/data/catalog_data.json`](docs/data/catalog_data.json) через
`fetch()`. Обновление раз в год (или чаще, пока идёт наполнение) не требует
сервера — только пересборку и коммит.

## Как обновить данные

1. Положить новую версию Excel-основы в `db/sources/osnova_bd.xlsx` (имена
   листов и столбцов — как сейчас; номер-префикс листа «11. …» не важен)
2. Пересобрать базу и выгрузку (нужен `openpyxl`: `pip install openpyxl`):
   ```bash
   cd db
   python build_db.py        # osnova_bd.xlsx -> rzd.db (+ RZD.md)
   python export_catalog.py  # rzd.db -> ../docs/data/catalog_data.json
   ```
   `git diff RZD.md` покажет, что поменялось в источнике.
   Компетенции и авторизации депо с действующим клеймом сборка берёт не из листов
   «Депо_Компетенц» / «Депо_Авторизац», а из `db/sources/rsfgt_registry.json` (см. `РЕЕСТР_КЛЕЙМЕНИЯ.md`).
   Слепок обновляется раз в месяц: `python rsfgt_receiver.py`, затем выгрузка реестра
   https://rsfgt.ru/Stamps/IssuedCerts из браузера (код — в начале `rsfgt_receiver.py`):
   сайт не отвечает на запросы скриптов.
   Если добавились логотипы — положить в `db/sources/logos/{ID}.svg|png` и перед
   экспортом запустить `python build_logos.py`.
3. Если добавились новые фото — сложить их в `docs/Photo/` (имя файла вида
   `<Категория> <Завод> <модель>.jpg`, как уже лежат) и пересобрать:
   ```bash
   cd db
   python match_photos.py    # docs/Photo/ -> photo_match_results.json (сопоставление файла с id вагона)
   python build_photos.py    # -> docs/photos/{id}.jpg + docs/photos/thumb/{id}.jpg
   python export_catalog.py  # подхватит наличие фото в catalog_data.json
   ```
   `match_photos.py` сопоставляет по модели и заводу из имени файла — стоит
   проверить `photo_match_results.json` (ключ `unmatched`) на случай, если
   что-то не нашлось в каталоге.
4. Проверить локально:
   ```bash
   cd ../docs
   python -m http.server 8000
   # открыть http://localhost:8000
   ```
5. Закоммитить и запушить — GitHub Pages обновится сам за пару минут

## Локальный запуск

Открывать `docs/index.html` напрямую (`file://`) не получится — браузер
блокирует `fetch()` для локальных файлов. Нужен любой веб-сервер:

```bash
cd docs
python -m http.server 8000
```

## Аналитика

В `docs/index.html` в `<head>` оставлено место под счётчик посещений (искать
комментарий «Аналитика»). Сайт статический — свой сервер для сбора
статистики не нужен, подключается сторонний счётчик. Варианты:

- **Яндекс.Метрика** — бесплатно, без ограничений, привычный интерфейс.
  Требует создать аккаунт на metrika.yandex.ru и вставить выданный код
  счётчика вместо комментария.
- **GoatCounter** — бесплатно, open-source, минималистичная статистика без
  профилирования пользователей.
- **Plausible** — приятный интерфейс, но бесплатно только self-hosted
  (нужен свой сервер) или платная подписка на облачную версию.

Заводить аккаунт нужно самостоятельно — это единственный шаг, который
нельзя сделать за вас.
